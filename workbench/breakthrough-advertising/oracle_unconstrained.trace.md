> 用途：这是开发期内部审计件，不进入公开任务说明，也不提供给被评 Agent。它把

## 1. 判定约定

- `E`（explicit）：正文直接表达关系的方向、边界或条件，judge 无需从书中补桥。
- `C`（connected）：关系不只被提到，还在相邻段落或跨节回收中承担下游功能。
- 本表只证明“Oracle 中有可判定表达”，不替代 Human Owner 对金卡本身的批准。
- 四个历史案例均按作者论证中的功能处理；正文对烟草、医学、工程与时代性主张保留归属和限定。

| P-06-03 | L63–67 | Complexity objection → Simplification；不改事实只换视角 → Lifebuoy 保留药味并反转意义。 |
| P-07-01 | L71–73 | How-demand 出现 → 机制按认知状态命名/描述/前置 → 次级主张证明主承诺。 |
| P-07-02 | L75–79 | 旧方案弱点 → 读者损害 → 本品对应消除；Fire Injectors 完整交织并准备 authority。 |
| P-07-03 | L81 | 特定受众 × 特定媒介 × 熟悉惯例 → 条件性迁移既有可信度。 |
| P-08-01 | L93–105 | 拆分后的多功能交织 → saturation/新问题触发 shift → 非固定 architecture → 改关系即改广告。 |
| P-08-02 | L87–89 | Documentation/Mechanization 分型 → reader readiness/need → Verification placement。 |

结论：`16/16` 条 mandatory paths 均以有方向的链条出现；没有把终点结论拆出来重复记分。
