# Benchmark V1：基准问题

## 1. 要测量什么

给定一本完整的非虚构作品和固定篇幅，模型能否同时完成两类重构：

1. **认知结构保留**：重建作者形成判断时使用的书特异问题、命题关系、推理路径、条件边界、立场转换和构成性材料；
2. **篇章关系重构**：把这些内容组织成一篇有中心线、真实推进、材料层级和有效收束的文章，而不是正确但模块化的知识笔记。

认知结构不是关键词覆盖率，也不是彼此独立的观点列表。它由命题／材料节点、有方向关系和核心路径组成。

篇章关系也不是句式相似度或“人味”。它关注：

- 原书重要材料之间的修辞功能和全书层级是否被保留；
- 候选文章的后一部分是否真实使用前一部分建立的前提、问题或转折；
- 章节顺序是否具有思想上的必要性；
- 案例是否参与论证；
- 结尾是否由前文推进出来。

详细契约：

- [认知结构 Rubric 契约](cognitive-structure-contract.md)
- [篇章关系重构评分契约](discourse-reconstruction-contract.md)

## 2. V1 评分对象

Pilot 并列报告以下字段：

| 指标 | 含义 | 当前状态 |
|---|---|---|
| `cognitive_relation_coverage` | 书特异认知关系的加权覆盖 | 认知主指标 |
| `complete_core_path_rate` | 必需／替代认知路径完整通过的比例 | 认知主指标 |
| `authorial_edge_recovery` | 原书作者关系边的修辞功能和下游作用恢复 | 篇章主指标 |
| `editorial_coherence` | 候选文章内部的局部推进、全局顺序、中心线、案例和收束 | 篇章主指标 |
| `discourse_reconstruction` | 篇章维度内部的确定性聚合 | Pilot 诊断指标 |
| `hard_constraints` | 字数、文件、格式、任务完成与复制率等程序检查 | 独立报告 |

编辑性连贯必须进一步报告：

```text
local_progression
global_order
spine_connectivity
example_integration
closure
```

“抵抗常识化与空洞化”仍不作为一个凭印象的独立总分。它通过具体失败进入认知关系、作者关系边和校准集，例如：

- 只保留主题词或结论；
- 用领域常识替代书特异机制；
- 关系正确但失去在全书中的控制、转折或收束作用；
- 模块彼此并列，缺少真实推进；
- 案例退化为装饰；
- 通用结尾可以替换到大量同领域文章。

最终单一 `reward` 的跨维度组合尚未冻结。开发阶段若 Harbor 必须接收一个标量，可以暂时使用 `cognitive_relation_coverage`；正式报告必须保留所有主指标和子指标。

## 3. 公开任务与隐藏 Rubric

公开 `instruction.md` 应当像真实的编辑委托：

- 有明确读者、用途、交付形式和篇幅；
- 要求文章保留作品最独特的判断与推理；
- 要求文章独立成文、有清楚中心线，而不是逐章摘要或观点清单；
- 允许重新安排原书材料；
- 不要求模仿原作者句式或风格。

公开任务不得列出：

- 这本书具体有哪些认知关系和路径；
- 哪些原文片段构成作者关系边；
- 哪个案例、转折或结尾回环会被抽查；
- 固定面板、编辑探针、Hard Negatives 和权重。

隐藏材料分成两张卡：

### 3.1 Book Card

包含：

- 核心认知结构；
- 节点角色、立场归属和认识论状态；
- 有方向的最小关系叶子；
- 必需路径与替代路径；
- 构成性案例和说明性案例；
- 来源锚点、判定边界和权重。

### 3.2 Discourse Card

包含：

- 有意义的作者关系边池；
- 原书 Source Anchor 对；
- 对应的篇章／修辞角色和下游依赖；
- 分层固定面板和随机种子；
- 编辑性连贯探针；
- 受控扰动和预期指标变化；
- 篇章维度内部权重。

## 4. 认知结构评分

Judge 不直接给整篇文章总体印象分。认知流水线：

1. Evidence Locator 寻找候选引文；
2. Relation Adjudicator 判断目标关系；
3. Quote Validator 验证引文和上下文；
4. Graph Aggregator 计算覆盖和路径完整。

封闭文本原则：Judge 可以处理同义表达、代词、省略和分散表达，但不能用原书知识替候选文章补入缺失的实质性前提。

### 4.1 关系覆盖

对认知结构 `S`：

\[
C_S = \frac{\sum_r w_r y_r}{\sum_r w_r}
\]

### 4.2 核心路径完整

- `mandatory` 路径全部关系通过才完整；
- 同一 `alternative_group` 至少一条替代路径完整；
- 一个结构的必需路径和替代组全部满足时，`path_complete = 1`。

最终结论通常是路径终点，不在路径外重复获得高权重。只写结论不能获得路径分。

## 5. 篇章关系重构评分

### 5.1 作者关系边恢复

作者关系边不是任意段落对，而是从审核后的 Source Anchors 中建立的、有明确意义的边，例如：

```text
能力边界 → 战略选择
反例 → 机制转折
前部问题 → 后部收束
多个章节 → 综合判断
```

内容正确性作为门槛：

\[
a_e = g_e \times (0.5r_e + 0.5d_e)
\]

- `g_e`：关联认知关系正确；
- `r_e`：原书修辞功能／层级被保留；
- `d_e`：候选文章后续内容实际使用该关系。

这避免同一语义关系在两个维度重复计分。

作者边来自预先审核的边池，并使用分层固定面板。所有模型使用同一面板；正式输出产生后不重新抽样。Pairwise 判断执行 A/B 位置反转。

### 5.2 编辑性连贯

编辑性连贯由候选文章内部关系和受控扰动测量：

1. `local_progression`：相邻段落是否存在可识别关系、向前依赖和新增推进；
2. `global_order`：交换主要文章单元后，原顺序是否在思想上更必要；
3. `spine_connectivity`：主要单元是否都能说明如何推进中心问题，孤立模块比例有多高；
4. `example_integration`：案例是否承担证据、反例、边界、转折、应用或综合功能；
5. `closure`：结尾是否回收开头、依赖正文并且非通用。

Pilot 默认：

\[
E = 0.30E_{local}
+0.30E_{order}
+0.20E_{spine}
+0.10E_{example}
+0.10E_{closure}
\]

篇章维度内部可暂用：

\[
D = 0.5A + 0.5E
\]

但认知维度与篇章维度如何合成最终排行榜分数仍不冻结。

## 6. 案例规则

认知结构继续区分：

- `constitutive`：案例参与结论形成，删除会破坏认知路径；
- `illustrative`：案例只帮助说明，可以替换或省略。

篇章维度另问：

> 候选文章中被选择保留的案例，是否在新文章里真实承担论证功能？

因此一个案例可能：

- 在认知上可选，但在候选文章中使用得很好；
- 在认知上必需，却被候选文章降格成装饰；
- 语义正确出现，但被放到错误位置，破坏转折或边界。

两个维度分别判定，不互相替代。

## 7. 样本和 Rollout

V1 正式目标为 5 本书、至少 3 个非虚构领域。工程验证：

1. 1 本开发书用于制作 Book Card、Discourse Card、Oracle、Judge Prompt 和校准扰动；
2. 开发书允许迭代，不进入对外主分；
3. 冻结协议后，至少 2 本保留书运行 Pilot；
4. 每书每模型默认 3 次 Rollout；
5. 报告均值、标准差和 Judge 分歧；
6. `best-of-k` 只作诊断。

关系、边和探针数量由书的结构与文章长度决定，不以凑固定数量为目标。

## 8. 裁判资格考试

### 8.1 认知校准

最低包括：语义保持改写、只保留结论、删除关系、删除构成性案例、常识替换、术语堆砌、删除限定、关系反转和立场误认。

### 8.2 篇章校准

最低包括：

- 不改变内容的主要章节交换；
- 把转场统一压成“此外／其次”；
- 改成“定义—案例”模块；
- 移动案例到错误位置；
- 用通用总结替换结尾；
- 只改变措辞、不改变关系和组织的语义保持改写。

预期原则：

- 章节交换可以保持认知覆盖，却降低 `global_order`；
- 模块化改写可以保持术语覆盖，却降低中心线和案例嵌入；
- 通用结尾只影响 `closure`；
- 语义保持改写不应系统性下降。

关键扰动无法被识别时，不得冻结该任务。

## 9. 统计和跨模型比较

同一本书内的关系、作者边和编辑探针相互相关，不能把它们当成来自不同书的独立样本。

- 单书报告面板／探针均值和 Bootstrap 区间；
- 多次 Rollout 报告均值与标准差；
- 跨书不池化叶子，先每书归一化再宏平均；
- 跨书置信区间以书为聚类单位；
- 同一冻结边上可补充模型 A/B Pairwise 胜率；
- A/B 顺序反转冲突记为平局或分歧。

## 10. 冻结顺序

正式结果产生前依次冻结：

1. 公开任务和篇幅；
2. 书稿版本与哈希；
3. Book Card；
4. Discourse Card 和链接的 Book Card 哈希；
5. Oracle 与正向锚点；
6. Locator、Judge Prompt、模型和参数；
7. 作者边面板、随机种子和编辑探针算法；
8. 聚合和失败处理；
9. Rollout 次数；
10. 校准文本和预期变化；
11. Harbor 与 Agent scaffold。

正式模型结果后修改任何关系、边、面板、探针或权重，都必须形成新版本并重跑所有模型。

## 11. 满分和效度

必须证明：

- 至少一个 Oracle 在规定篇幅内可达到高认知分和高篇章分；
- 语义等价且组织不同的合格文章也能高分；
- 高认知覆盖的知识笔记在篇章维度不会自动满分；
- 流畅但通用的文章在认知和作者边维度不会高分；
- 正确重组不受机械章节顺序惩罚；
- 错误重排、孤立模块、装饰案例和通用结尾能被定向识别。

## 12. V1 不声称测量什么

- 不声称直接测量“灵魂”或“人味”；
- 不声称判断文本由人还是 AI 写成；
- 不要求模仿作者的词汇、句法和节奏；
- 不以原书表面顺序或单一参考文章作为唯一正确组织；
- 不把局部语言流畅等同于全局编辑性连贯；
- 不把未经校准的整体 1–10 分当作主指标；
- 不用单本书代表全部非虚构作品；
- 不声称当前临时 `reward` 已是最终排行榜公式。
