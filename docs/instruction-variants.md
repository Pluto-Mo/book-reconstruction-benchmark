# Instruction 信息充分度实验契约

## 1. 真实使用场景

本 Benchmark 的公开任务来自一个具体的 AI 助学场景，而不是“替杂志写书评”或“为别人做复习材料”。

目标读者没有足够时间经常逐字读完整本书，希望先让 AI 完整阅读，再把一本以概念、模型和论证为核心的知识型非虚构作品压缩成一篇可以直接认真阅读的文章。

这个读者不满足于获得若干最终观点或“核心结论”。他希望在显著减少阅读时间的同时，仍然能够：

- 看清作者到底在解决什么问题；
- 理解作者独有的概念、模型和区分是怎样建立起来的；
- 跟随书中可观察到的论证推进，而不只是知道终点；
- 保留真正承担解释、证明、反例、边界或转折作用的材料；
- 避免把书特异的复杂判断压成任何同类书都能套用的常识；
- 得到一篇信息密度高、连续成文、值得认真阅读的文章。

这是一种“压缩共读”任务：AI 替读者承担完整阅读与第一次筛选的时间成本，但不能把原书最有认知价值和阅读价值的部分一并消除。

V1 评价的仍然是文本中可观察、可核验的认知结构和篇章关系。这里所说的“跟着作者思考”不指推断作者私下的心理过程，而指书稿中实际呈现的概念建立、命题关系、论证推进、材料功能、限定与收束。

## 2. 公开目标与隐藏测量必须分离

公开 `instruction.md` 必须让被测模型知道用户真正想得到什么，但不能替模型完成这本书的任务分析。

可以公开：

- 用户为什么需要压缩；
- 用户不只想获得结论；
- 用户希望理解概念、模型、论证和有意义的例子；
- 用户反对常识化、章节摘要、知识点清单和空泛 AI 总结；
- 文章需要连续成文、具有较高信息密度；
- 篇幅、输出路径、只使用书稿等硬约束。

不得公开：

- 这一本书具体有哪些认知关系、核心路径或关键结论；
- 哪个具体概念、案例、限定或转折必须出现；
- Book Card / Discourse Card 的叶子、边、面板、Hard Negatives、`pass_if`、权重或抽查点；
- 任何等价于给出单书 answer key 的提示。

原则是：**公开用户意图，隐藏评价操作化。**

如果一条要求只有读过隐藏 Rubric 才可能知道，它不是合法的隐含用户要求；如果一个优秀的人类执行者仅凭用户用途就应自然意识到它重要，则可以由隐藏 Rubric 把它进一步操作化。

## 3. 三个 Instruction 条件

三个版本不是简单的“长 / 中 / 短”，而是三个不同的**需求信息充分度条件**。

### 3.1 `natural`：主 Benchmark 条件

`natural` 是 V1 主榜默认条件。

它模拟一个认真使用 AI 共读的普通用户：会说明自己的时间约束、阅读目的和明显偏好，但不会先替 AI 建好认知图、论证框架或评分清单。

它应该让任务足够明确，使隐藏 Rubric 的评价具有合法性；同时保留模型自行判断“这本书什么最重要、哪些材料承担什么功能、应该如何重组”的空间。

`templates/book-task/instruction.md` 固定为 `natural` 模板。

### 3.2 `explicit`：显式规格消融

`explicit` 在 `natural` 的基础上，把用户的高层质量偏好说得更完整，例如明确提醒模型关注：

- 核心问题；
- 书中特有的概念和模型；
- 论证怎样推进；
- 重要限定、反例和功能性案例；
- 连续成文和信息密度。

它仍然不得给出任何单书具体答案。

这个条件不进入主榜，用来估计：**当用户把任务规格说得更完整时，模型能力上限能被抬高多少。**

若 `explicit` 显著高于 `natural`，说明模型并非完全不会完成任务，而是较依赖 Prompt 脚手架完成前置任务分析。

### 3.3 `minimal`：隐含意图诊断

`minimal` 只保留用户用途和很少的方向性描述，例如“我没时间完整读这本书，希望通过你的文章真正读懂它，而不是只看普通摘要”。

它故意不展开模型、例子、论证推进、常识化等具体偏好。

这个条件不进入主榜，用来诊断：**模型能否从较模糊但真实的用户目标中自行展开隐含质量要求。**

`minimal` 低分不能单独解释为整书理解或压缩能力差，因为其中混入了意图展开能力。

## 4. 三个条件的解释

记：

- `E` = `explicit` 得分；
- `N` = `natural` 得分；
- `M` = `minimal` 得分。

V1 主能力结果使用 `N`。

辅助诊断可以报告：

```text
prompt_scaffolding_gain = E - N
implicit_intent_drop = N - M
```

它们不与主分混合为一个排行榜标量。

典型解释：

| 结果形态 | 解释 |
|---|---|
| `E / N / M` 都高 | 核心能力强，对用户表达也鲁棒 |
| `E` 高、`N` 中、`M` 低 | 能完成任务，但明显依赖 Prompt 脚手架 |
| `E / N` 高、`M` 低 | 阅读与重构能力较强，隐含意图展开较弱 |
| 三者都低 | 主要瓶颈更可能在整书理解、选择或重构本身 |
| 三者都接近满分 | 任务或 Judge 可能仍缺乏区分度，需要检查校准集 |

## 5. Harbor 原生映射

不为 Instruction 变体引入新的运行层、Reader Profile 文件、Prompt 编译器或自定义 Harbor 结构。

正式实例化时，每个实验条件都是一个**独立的标准 Harbor Task**，直接把对应文本写入该 Task 的 `instruction.md`：

```text
tasks/<book-id>-natural/
├── instruction.md
├── task.toml
├── environment/
├── solution/
└── tests/

tasks/<book-id>-explicit/
└── ...

tasks/<book-id>-minimal/
└── ...
```

三个条件必须固定：

- 同一书稿和 source hash；
- 同一目标篇幅；
- 同一 Harbor Agent scaffold；
- 同一工具、预算、采样参数和 rollout 数；
- 同一 Book Card、Discourse Card、Judge、verifier 和聚合方法；
- 只改变 `instruction.md` 中公开的需求信息充分度。

`task.toml [metadata]` 使用 Harbor 原生 metadata 记录：

```toml
instruction_variant = "natural" # natural | explicit | minimal
```

三者不是 Multi-step Task，也不得让同一次模型上下文先看到 `explicit` 再运行 `natural` 或 `minimal`。

## 6. V1 比赛阶段的最小执行方案

比赛阶段不要求所有书都三档全跑。

优先顺序：

1. 用同一本开发书跑 `explicit / natural / minimal`，确认三档是否真的产生可解释的区分；
2. 若成立，冻结 `natural` 为正式主任务模板；
3. 后续正式书优先运行 `natural`；
4. `explicit` 和 `minimal` 保留为消融 / 诊断条件，不与主榜样本直接混合。

如果三档只体现文字长短而没有稳定的能力差异，则应删除该消融，而不是为了形式保留三个版本。
