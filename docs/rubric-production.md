# Agent 辅助的 Rubric 生产协议

本协议用于在人工时间有限时，为每本书制作可审计的认知结构 Book Card。Agent 可以承担提取、拆分、审计和红队工作，但最终冻结权属于 Benchmark 作者。

Rubric 的目标不是收集尽可能多的观点，而是建立：

```text
完整书稿
→ 核心问题
→ 认知结构
→ 命题节点
→ 有方向关系
→ 必需 / 替代路径
→ 可独立判定的关系叶子
```

详细语义见 [认知结构 Rubric 契约](cognitive-structure-contract.md)。

## 1. 产物边界

每本书至少产生：

```text
book source
    ↓
source map + document SHA-256
    ↓
core cognitive structures
    ↓
nodes + typed relations + paths
    ↓
Book Card
    ↓
Oracle / equivalent positive anchors
    ↓
calibration variants
    ↓
Judge criteria
```

节点或关系数量不是目标。有效 Rubric 必须让以下输出得到不同结果：

- 完整认知重构；
- 只保留最终结论；
- 只覆盖主题词；
- 常识替换；
- 删除一条关键关系；
- 删除构成性案例；
- 删除普通说明例；
- 关系反转；
- 立场归属错误；
- 语义保持改写。

## 2. 角色分工

### 2.1 Rubric Builder Agent

输入完整书稿、固定构念和 Schema，生成候选：

- 全书核心问题簇；
- 认知结构划分；
- 节点、角色、立场归属和认识论状态；
- 有方向关系；
- 必需路径和替代路径；
- 构成性与说明性案例；
- 来源定位；
- `pass_if`、`fail_if`、假阳性和权重建议。

Builder 只能输出 `draft`，不能自行标记为 `human_reviewed` 或 `frozen`。

### 2.2 Rubric Auditor Agent

逐结构检查：

- 是否能在原书找到明确来源；
- 是否只是领域常识；
- 是否把一组复杂关系错误压成单个观点；
- 节点的立场归属是否正确；
- 暂时假设、让步和作者最终立场是否混淆；
- 关系方向、条件、边界和否定范围是否完整；
- 构成性案例是否被误标为普通例子；
- 是否存在重复关系或虚假拆分；
- 是否要求复述固定措辞；
- 是否能从候选文章中独立取证；
- Oracle 是否能在固定篇幅内同时满足全部路径。

Auditor 输出问题清单，不直接覆盖原卡。

### 2.3 Red-Team Agent

为每个高权重结构生成受控变体：

1. 完整正确重构；
2. 语义保持但重组顺序；
3. 只保留最终结论；
4. 删除一条核心关系；
5. 删除构成性案例；
6. 删除普通说明例；
7. 流畅但常识化；
8. 使用术语但关系错误；
9. 删除限定；
10. 关系反转；
11. 把反方观点写成作者观点；
12. 漂亮空话。

每个变体必须声明：

- 只改变了什么；
- 哪些关系应改变标签；
- 哪些关系不应受影响；
- 路径完整率预期如何变化。

Benchmark 作者确认后才可进入校准集。

### 2.4 Human Owner

人工集中判断：

- Benchmark 构念；
- 一级认知结构；
- 高权重和关键关系；
- 节点的立场归属与认识论状态；
- 构成性案例；
- 必需路径和可替代路径；
- 来源忠实性；
- 满分可达性；
- 权重和关键边界；
- 校准变体是否只改变目标变量；
- 最终冻结状态。

## 3. 来源映射

在生成结构之前，先给书稿建立稳定定位。推荐：

```text
chapter-03/section-02/p0042-p0048
```

每个任务记录输入 Markdown 的 SHA-256；书稿变化后，原 Book Card 自动失效并重新审查。

`source_anchor` 至少包含：

- 稳定 `locator`；
- 忠实的证据摘要；
- 该材料在作者论证中的功能；
- 可选章节与小节名。

默认不把受版权保护的长段原文写入仓库。

注意区分：

| 名称 | 含义 | 阶段 |
|---|---|---|
| `source_anchor` | 证明 Rubric 节点或关系来自原书 | 构建 |
| `argument_evidence` | 作者用来支持或反驳观点的材料 | 认知结构 |
| `submission_evidence` | 候选文章中用于运行时判决的引文 | 评分 |

## 4. 第一步：确定核心问题与结构边界

不要先摘“金句”或观点。

Builder 先回答：

1. 作者反复试图解释或解决什么问题？
2. 哪些问题共同构成一套相对独立的认知结构？
3. 删除哪个结构会显著改变读者对全书的理解？
4. 哪些内容只是背景、重复说明或修辞展开？

一个认知结构通常包含：

- 一个明确的中心问题；
- 两个以上命题或材料节点；
- 一条以上有方向关系；
- 至少一条可以说明作者如何形成判断的路径。

结构之间可以互相引用，但不要为了凑固定数量而切碎。

## 5. 第二步：建立节点

节点是参与推理的内容单元，不是评分叶子。

每个节点记录：

- `statement`：忠实、简洁的命题或材料描述；
- `role`：问题、主张、假设、机制、条件、案例、反例、结论等；
- `stance_owner`：作者、对手、引用来源、假设主体或中性材料；
- `epistemic_status`：主张、假设、让步、否定、限定、保留或观察；
- `source_anchor_ids`；
- `essential`：是否属于满分结构的必要节点。

### 5.1 节点审计问题

- 这是作者自己的判断，还是作者正在讨论、引用或反驳的判断？
- 它是最终主张，还是为了推演而暂时假设？
- 它是独立命题，还是只是另一个节点的修辞改写？
- 它的删除是否会让某条关键关系失去意义？

节点本身通常不单独计分；它通过关系进入评分。

## 6. 第三步：建立最小有方向关系

最小评分叶子是可独立判定的关系，例如：

- `causes`；
- `supports`；
- `jointly_supports`；
- `explains`；
- `qualifies`；
- `limits`；
- `refutes`；
- `contradicts`；
- `distinguishes`；
- `exemplifies`；
- `instantiates`；
- `enables`；
- `implies`；
- `precedes`。

一个关系可以有多个来源节点。例如两个前提共同支持结论：

```text
P1 + P2 --jointly_supports--> T
```

### 6.1 关系停止条件

一条关系只有同时满足以下条件，才可以停止拆分并成为 Judge 叶子：

1. 有明确来源节点和目标节点；
2. 有清楚的方向和关系类型；
3. 只要求一次窄语义判断；
4. 必须保留的机制、条件、边界、立场或案例身份已写入 `required_facets`；
5. 候选文章中可以引用直接依据；
6. 不需要 Judge 用原书知识补入缺失前提；
7. 有明确 `pass_if` 和 `fail_if`；
8. 有至少一个常见假阳性；
9. 有原书来源锚点；
10. 允许语义等价表达；
11. 能独立判定，但仍被保留在所属路径中。

不合格叶子：

- “本书讲了反馈”；
- “模型理解了核心思想”；
- “文章很有深度”；
- “作者认为训练很重要”；
- “充分解释了整个训练理论”。

合格叶子：

- “候选文章说明反馈用于定位具体错误，并改变下一轮练习决策”；
- “候选文章明确把案例 E 用作反驳假设 H，而不是作者支持 H 的证据”；
- “候选文章保留条件 C 对结论 T 的适用范围限制”。

## 7. 第四步：建立必需路径和替代路径

关系不能拆完后扔进一个扁平池。

### 7.1 必需路径

`mandatory` 路径表示满分必须恢复的完整推进：

```text
H --被 E 反驳→ M --支持→ T
```

该路径中任何关系失败，路径都不完整。

### 7.2 替代路径

如果作者用两条不同但等价的论证路径支持同一判断，可以建立多个 `alternative` 路径，并使用同一个 `alternative_group`。

同组中至少一条完整即可，不要求候选文章机械复刻所有替代论证。

### 7.3 路径审计问题

- 只写最终结论时，具体缺失哪些关系？
- 每条关系是否真的都不可省略？
- 哪些关系共同存在才构成作者的判断？
- 是否允许另一种忠实组织方式达到满分？
- 是否存在把同一内容重复拆分、从而重复计分的问题？
- 所有 `critical` 关系是否至少进入一条必需或替代路径？

## 8. 第五步：分类案例

### 8.1 构成性案例

满足任一条件时，优先标为构成性：

- 它推翻关键假设；
- 它引出核心机制；
- 它建立概念区分；
- 它是作者结论不可替代的事实基础；
- 删除后读者不知道作者为什么转向后续判断。

字段：

```json
{
  "function": "constitutive",
  "preservation": "required"
}
```

### 8.2 说明性案例

若案例只帮助解释已清楚表达的机制，标为：

```json
{
  "function": "illustrative",
  "preservation": "replaceable"
}
```

不要因为模型没有复述全部故事而机械扣分。

## 9. 第六步：写判定边界

每条关系至少包含：

```json
{
  "id": "R-01",
  "source_node_ids": ["N-01", "N-02"],
  "target_node_ids": ["N-03"],
  "relation_type": "jointly_supports",
  "requirement": "候选文章必须保留两个前提共同支持结论的结构。",
  "required_facets": [
    "direction",
    "condition",
    "stance_owner"
  ],
  "source_anchor_ids": ["SA-001"],
  "acceptable_paraphrases": [
    "允许分散表达，只要两个前提和共同支持关系都明确。"
  ],
  "pass_if": [
    "候选文章明确表达两个前提及其共同作用。"
  ],
  "fail_if": [
    "只写结论。",
    "只保留其中一个必要前提。"
  ],
  "common_false_positives": [
    "三个概念同时出现，但没有表达共同支持关系。"
  ],
  "contradiction_patterns": [
    "把其中一个前提写成反对结论的理由。"
  ],
  "weight": 1.0,
  "critical": true
}
```

`weight` 是同一结构内的局部重要性，不表示制作难度。默认等权；只有明确理由时才提高权重。

最终结论不应在路径之外重复获得一份独立高权重。

## 10. 第七步：写常识陷阱

`genericity_traps` 不是另一套总体审美分，而是记录候选文章最容易出现的假阳性：

- 只出现主题词；
- 只给最终结论；
- 用领域常识替代书特异机制；
- 删除条件后把判断绝对化；
- 用漂亮表达遮蔽关系缺失；
- 把构成性案例改成无关例子；
- 把反方观点误写成作者观点。

每个陷阱必须引用具体 `related_relation_ids`，以便校准时知道哪些关系不应错误通过。

## 11. 证据定位与关系判决分离

运行时职责：

```text
Evidence Locator
→ 输出候选引文和位置，不给分

Relation Adjudicator
→ 读取目标关系和候选引文，给出窄判断

Quote Validator
→ 验证引文存在、位置正确、没有断章取义

Graph Aggregator
→ 计算关系覆盖和路径完整度
```

Judge 可以重新组织候选文章已经明确表达的命题，但不得补入候选文章缺失的实质性桥接命题。

第一次定位未找到证据时，必须按冻结规则进行二次定位或全文复查，不能立即把 Locator 的召回失败当作模型错误。

## 12. 自动审计规则

冻结前至少检查：

- 所有 Source Anchor、Structure、Node、Relation、Path ID 唯一；
- 所有引用 ID 可解析；
- 每个关系的来源和目标节点存在于同一结构；
- 每条路径引用的关系存在于同一结构；
- 每个关键关系至少属于一条必需或替代路径；
- 每个 `essential` 节点至少参与一条关系；
- 构成性案例使用 `preservation = required`；
- 所有权重为正；
- 每条关系都有 `pass_if`、`fail_if` 和常见假阳性；
- 没有空数组占位符；
- 书稿哈希与实际输入一致；
- `frozen` 卡有人工审核人和冻结时间；
- Oracle 在固定篇幅内可满足全部必需结构。

运行：

```bash
uv run scripts/validate_book_card.py \
  --card templates/book-task/tests/gold/book_card.example.json \
  --schema schemas/book-card.schema.json
```

Schema 和脚本只能检查结构一致性，不能证明内容忠于原书。高权重关系、构成性案例和必需路径必须人工全查。

## 13. 计分输出

Pilot 至少保存：

```json
{
  "cognitive_relation_coverage": 0.68,
  "complete_core_path_rate": 0.31,
  "hard_constraints": 1.0,
  "genericity_failure_rate": 0.14,
  "judge_disagreement_rate": 0.08
}
```

其中：

- 关系覆盖提供渐进分辨率；
- 路径完整率阻止零散观点冒充完整重构；
- `genericity_failure_rate` 和分歧率是诊断；
- 最终单一 `reward` 组合在开发书试跑后再冻结。

## 14. 校准与冻结

最低校准集合：

| 类型 | 预期 |
|---|---|
| 语义保持改写 | 关系和路径不变 |
| 正确重组顺序 | 若认知功能不变，应保持得分 |
| 只保留最终结论 | 终点可能出现，但核心路径不完整 |
| 删除一条关键关系 | 对应路径失败 |
| 删除构成性案例 | 对应关系和路径失败 |
| 删除说明性案例 | 原则上不应影响已清楚表达的机制 |
| 常识替换 | 书特异关系不得通过 |
| 术语堆砌 | 不因关键词共现而通过 |
| 删除限定 | 边界关系失败 |
| 关系反转 | 方向关系失败 |
| 立场误认 | 立场和认识论状态失败 |
| 错误重排 | 若改变认知功能，应扣分 |

冻结门槛至少分别报告：

- 假阳性；
- 假阴性；
- 关系反转识别；
- 立场误认识别；
- 语义保持一致性；
- 路径完整识别；
- Judge 分歧率。

关键关系反转、立场误认或构成性案例删除仍被判为完整通过时，任务不得冻结。

## 15. 正式运行纪律

Rubric、公开 instruction、Judge、权重和校准预期必须在查看正式模型结果前冻结。

正式结果后发现问题：

1. 记录失败案例；
2. 新建 schema / card / prompt 版本；
3. 更新校准集；
4. 对所有对比模型重新运行。

禁止只针对某一个模型的输出补节点、删节点或改权重。
