# Agent 辅助的 Rubric 生产协议

本协议用于在人工时间有限时生产每本书的细粒度 Book Card。Agent 可以承担提取、拆分和红队工作，但最终冻结权属于 Benchmark 作者。

## 1. 产物边界

每本书最终至少产生：

```text
book source
    ↓
source map
    ↓
8–12 条书特异关系
    ↓
每条关系 3–5 个二元原子
    ↓
Book Card
    ↓
Judge criteria
    ↓
校准变体与人工标签
```

30 小时 Pilot 建议每书先控制在 **25–40 个有效叶子**。节点数量不是目标；有效节点必须能让完整理解、只保留结论、常识替换和关系反转得到不同分数。

## 2. 角色分工

### Rubric Builder Agent

输入完整书稿、固定构念和 Schema，生成：

- 全书问题意识；
- 候选核心关系；
- 来源定位；
- 原子条件；
- 正反例和权重建议。

Builder 只能提出候选项，不能把自己的生成结果标记为 `frozen`。

### Rubric Auditor Agent

逐项检查：

- 是否能在书中找到依据；
- 是否混合了多个命题；
- 是否与其他节点重复；
- 是否只是一般写作质量；
- 是否可能看到关键词就误判；
- 是否把领域常识错误当作书特异内容；
- 是否要求复述固定措辞；
- 是否能从候选文章中直接取证。

Auditor 输出问题清单，不直接覆盖原卡。

### Red-Team Agent

为每个高权重关系生成受控变体：

1. 完整且正确；
2. 只保留结论；
3. 流畅但常识化；
4. 使用术语但因果错误；
5. 删除限定条件；
6. 反转关系；
7. 纯语言改写但语义保持。

每个变体必须声明“只改变了什么”。Benchmark 作者确认后才可进入校准集。

### Human Owner

人工只集中判断高价值部分：

- 构念和一级结构；
- 高权重关系；
- 来源是否忠实；
- 满分是否可达；
- 权重和关键边界；
- 校准变体是否只改变目标变量；
- 最终 `frozen` 状态。

## 3. 来源映射

在生成关系之前，先给书稿建立稳定定位。推荐格式：

```text
chapter-03/section-02/p0042-p0048
```

Book Card 不应依赖易变化的自然页码。每个任务还要记录输入 Markdown 的 SHA-256；书稿变化后原 Book Card 自动失效，必须重新审查。

来源锚点至少包含：

- 稳定 locator；
- 忠实的证据摘要；
- 可选章节与小节名。

默认不把受版权保护的长段原文写入仓库。

## 4. 关系级拆分

一条关系描述概念之间的结构，例如：

- 原因 → 结果；
- 条件 → 结论；
- 常见解释 ↔ 作者反驳；
- 表面相似概念之间的区别；
- 证据在论证中的功能；
- 原则 → 推论或行动设计。

不合格关系：

- “本书讲了反馈”；
- “模型理解了核心思想”；
- “文章很有深度”；
- “总结准确且完整”。

它们没有明确关系，也无法稳定取证。

## 5. 原子停止条件

一个节点只有同时满足以下条件才可停止拆分：

1. 只包含一个可判真的命题；
2. 候选文章中可以引用一段明确证据；
3. 没有证据时可以直接判为 0；
4. 有明确 `pass_if` 和 `fail_if`；
5. 有至少一个常见假阳性；
6. 有来源锚点；
7. 允许语义等价表达；
8. 不把语言流畅、篇幅或术语密度当作理解；
9. 不依赖 Judge 对整篇文章的总体印象；
10. 与兄弟节点可以独立得分。

例如，不应写：

> 是否充分解释了反馈机制并提出了可执行改进方案。

应拆成：

- 是否说明反馈用于定位具体错误；
- 是否说明反馈会改变下一轮练习决策；
- 是否指出缺乏反馈会使错误被重复；
- 改进方案是否明确提供反馈来源。

## 6. Book Card 字段

每个原子至少包含：

```json
{
  "id": "R-01-A-02",
  "requirement": "候选文章建立反馈、错误定位和下一轮训练调整之间的关系。",
  "source_anchor_ids": ["R-01-S-01"],
  "acceptable_paraphrases": [
    "允许不用原书术语，只要三者之间的功能关系明确。"
  ],
  "pass_if": [
    "明确说明反馈如何识别错误，并影响下一步训练。"
  ],
  "fail_if": [
    "只说反馈很重要。",
    "只提到分数或结果，没有说明后续调整。"
  ],
  "common_false_positives": [
    "出现“反馈”关键词，但没有恢复训练闭环。"
  ],
  "contradiction_patterns": [
    "把反馈描述为训练完成后的无关附加信息。"
  ],
  "weight": 1.0,
  "critical": false
}
```

`weight` 是相对于同一关系下兄弟原子的局部权重，不表示制作难度。默认等权；只有少数确有理由的节点使用 2 倍权重。

## 7. 自动审计规则

冻结前至少运行以下检查：

- 所有 ID 唯一；
- 所有 Atom 至少引用一个 Source Anchor；
- 所有 `source_anchor_ids` 可解析；
- 所有关系和原子权重为正；
- 每个原子都有 `pass_if`、`fail_if` 和常见假阳性；
- 没有空数组占位符；
- Book Card 的书稿哈希与实际输入一致；
- `status` 只有人工审核后才能从 `draft` 变为 `human_reviewed` 或 `frozen`。

Schema 只能验证结构，不能证明内容忠于原书。来源忠实性仍需人工抽查，且高权重关系必须全查。

## 8. Judge 打包

每个 Judge 调用只处理一个关系或一小组高度相关原子。推荐：

```text
tests/cognitive_structure/
├── relation-r01.toml
├── relation-r02.toml
└── relation-r03-high-risk.toml
```

默认批次为 3–8 个二元原子。以下情况使用逐原子模式：

- 条件或否定范围容易混淆；
- 候选文章可能在不同位置自相矛盾；
- 校准中出现高假阳性；
- 原子权重较高；
- 需要独立复核。

Judge 不读取完整书稿。它读取候选文章和已冻结的相关卡片；来源摘要用于界定标准，而不是让 Judge 临场重新总结整本书。

## 9. Judge 结果契约

每个原子保存：

```json
{
  "criterion_id": "R-01-A-02",
  "verdict": 1,
  "evidence": {
    "status": "found",
    "quote": "候选文章中的最短原文证据"
  },
  "contradiction_found": false,
  "reason": "证据明确恢复了反馈如何改变下一轮训练。",
  "confidence": 0.88,
  "judge_model": "provider/model",
  "prompt_version": "judge-v1"
}
```

没有证据时：

- `evidence.status = "none"`；
- `evidence.quote = ""`；
- `verdict = 0`。

引文必须经过字符串存在性检查。Judge 的自然语言理由和置信度用于审计，不直接进入总分。

## 10. 校准与冻结

至少准备以下校准类型：

| 类型 | 预期作用 |
|---|---|
| 语义保持改写 | 防止 Judge 只认固定措辞 |
| 只保留最终结论 | 检查推理节点是否仍会错误得分 |
| 常识替换 | 检查书特异性 |
| 术语堆砌 | 检查关键词假阳性 |
| 删除限定 | 检查边界 |
| 关系反转 | 检查方向 |
| 漂亮空话 | 检查整体印象偏差 |

冻结门槛不只看一个总 F1。至少分别报告：

- 假阳性；
- 假阴性；
- 关系反转识别；
- 语义保持改写的一致性；
- 不同 Judge 或重复调用之间的分歧率。

关键关系反转样本若仍出现假阳性，该 Book Card 或 Judge Prompt 不得冻结。

## 11. 正式运行纪律

Rubric、Judge 和权重必须在查看正式模型结果前冻结。正式结果后发现问题，应：

1. 记录失败案例；
2. 新建版本；
3. 更新校准集；
4. 对所有模型重新运行。

禁止只针对某一个模型的输出补节点或改权重。
