# 认知结构 Rubric 契约 V1

本文冻结“每本书的隐藏 Rubric 应如何表示”的第一版契约。它不选择书目，不写任何正式金标准，也不冻结生产 Judge；它的作用是让下一步可以开始为开发书制作真实 Rubric，而不再把一本书拆成互不相干的观点清单。

## 1. 第一性目标

本 Benchmark 测量的是：

> 给定完整非虚构作品与固定篇幅，模型能否重建作者形成判断时使用的书特异认知结构，使读者获得作者的问题意识、概念关系、推理路径、条件边界与关键论证材料，而不是只得到正确但普通的最终结论。

这里的“认知结构”不是关键词集合，也不是摘要中的观点数量。它至少包含：

- 作者试图解决的核心问题；
- 命题、概念、案例和证据分别承担什么角色；
- 谁持有某个观点，以及作者是提出、暂时考察、部分承认、限定还是推翻它；
- 因果、支持、反驳、区分、条件、边界和推论如何连接；
- 哪些关系共同构成不可省略的核心路径；
- 哪些案例参与了结论的形成，而不只是帮助说明。

## 2. 阅读效用动机与构念边界

本项目的现实目的，是让人能够借助 AI 在高压缩条件下更高效地获取一本书真正独有的认知价值，而不是只获得一篇“主题正确”的摘要。

当前设计从四类阅读与学习思想中提取项目级启发：

- 《如何阅读一本书》：重构应保留全书骨架、关键概念、命题和论证，而不是只摘取句子；
- 《刻意练习》（安德斯·埃里克森）：学习价值来自可用于识别、解释和纠错的心理表征，不只是记住结论；
- 《实用性阅读指南》：压缩结果应使知识可以被回忆、输出和用于行动；
- 《深度阅读》：压缩不是均匀缩短，而是识别高价值内容并重新组织成可理解、可输出的结构。

这些书提供的是 Benchmark 的人类阅读动机，不替代每本正式书自己的金标准。

V1 主构念仍然是：

```text
固定篇幅下，对作者认知结构的忠实重构
```

“读完重构文章后是否更容易迁移和应用”属于后续效度验证。未来可以让一个只读 `submission.md`、不读原书的答题者完成机制、边界、反例和新情境问题，以验证结构分是否真的对应阅读效用；V1 不先把这一效果凭印象混入主分。

## 3. 公开任务与隐藏 Rubric 必须分离

### 3.1 公开 `instruction.md`

公开任务必须做到“目标清楚，但不泄露答案”。它告诉被测 Agent：

- 需要重构作者的核心认知结构，而不是逐章摘要；
- 需要保留关键推理路径、条件边界、立场转换和构成性案例；
- 允许重新组织文字，不要求复述固定措辞；
- 不得把作品压缩成领域常识或观点清单。

公开任务不得列出：

- 这本书具体有哪些核心关系；
- 哪个案例是必保案例；
- 哪个假设会被推翻；
- 每条关系的权重和 `pass_if`；
- 隐藏的反例、常识陷阱或校准样本。

### 3.2 隐藏 Book Card

隐藏 Book Card 回答的是：

- 这本书具体有哪些核心认知结构；
- 每个结构包含哪些命题节点和有方向关系；
- 哪些关系共同构成必需路径，哪些路径可以替代；
- 哪些案例是构成性的，哪些说明例可以替换；
- 什么算完整保留、只保留主题、关系反转或立场误认；
- 每项为何进入 Rubric，以及其原书来源在哪里。

因此：

```text
公开 instruction = 考试任务
隐藏 Book Card   = 这本书的满分结构
Verifier         = 按冻结契约判定候选文章
```

## 4. 不使用扁平“原子列表”

一本书的 Rubric 采用以下层级：

```text
Book
└── Cognitive Structure
    ├── Nodes
    ├── Typed Relations
    └── Required / Alternative Paths
```

### 4.1 节点

节点表示参与作者思考过程的内容单元，例如：

- 问题；
- 作者主张；
- 对手观点；
- 暂时假设；
- 前提；
- 中间机制；
- 条件与边界；
- 证据、案例或反例；
- 反驳与结论；
- 推论或行动原则。

节点本身通常不单独得分。它的意义由它与其他节点的关系决定。

### 4.2 最小评分叶子是“关系”

本项目仍可使用“认知原子”一词，但它被严格定义为：

> 最小、可独立判定、具有方向和语义类型的关系。

它不是关键词，也不是一句孤立命题。例如：

```text
反例 E --refutes--> 假设 H
机制 M --supports--> 结论 T
条件 C --qualifies--> 结论 T
概念 A --distinguishes--> 概念 B
前提 P1 + P2 --jointly_supports--> 结论 T
```

一个复杂论断可以拆成多条关系，但这些关系必须继续保留在同一个认知结构和路径中，不能拆完后作为彼此无关的叶子池。

### 4.3 认知结构允许是图，而不只是一条直线

作者可能采用：

- 线性因果链；
- 多个前提共同支持一个结论；
- 多条替代路径导向同一判断；
- 先假设、再让步、再反驳；
- 多个案例归纳出模式，再由反例限定；
- 概念区分后推出不同适用结论。

因此 schema 必须允许一个关系有多个来源节点和多个目标节点，并允许关系构成分支、汇合和替代路径。

## 5. 节点必须保留认识论身份

每个节点至少记录三件事：

### 5.1 论证角色

例如 `assumption`、`mechanism`、`counterexample`、`rebuttal`、`conclusion`。

### 5.2 立场归属

例如：

- `author`：作者自己的判断；
- `opponent`：作者正在反驳或修正的观点；
- `cited_source`：被引用者的观点；
- `hypothetical`：为了推演而暂时设定；
- `neutral`：事实、问题或不带立场的材料。

### 5.3 认识论状态

例如：

- `asserted`：作者主张；
- `assumed`：暂时假设；
- `conceded`：部分承认；
- `rejected`：被否定；
- `qualified`：被限定；
- `unresolved`：作者保留；
- `observed`：观察或材料。

如果候选文章把作者正在反驳的观点写成作者主张，即使关键词全部出现，也属于主认知结构错误，而不是语言风格问题。

## 6. 顺序是否计分只看认知功能

本 Benchmark 不要求机械复刻原书章节顺序。

判断标准只有一个：

> 改变顺序后，读者对观点归属、推理方向、条件边界或论证功能的理解是否改变？

- 若改变，则该顺序承担认知功能，必须通过节点状态和关系进入主分；
- 若不改变，则允许候选文章重新组织表达；
- 纯句式、节奏和修辞模仿不进入 V1 主分。

因此不再保留模糊的独立“作者性组织”维度。具有认识论功能的作者组织属于认知结构；纯语言风格暂不测量。

## 7. 案例分为构成性与说明性

### 7.1 构成性案例

构成性案例参与了作者概念、机制或结论的形成，例如：

```text
关键案例 E
→ 暴露常见解释 H 的缺陷
→ 引出机制 M
→ 支持作者判断 T
```

删除它会使读者无法理解作者为什么从 H 走到 T。此类案例必须在 Book Card 中标为：

```text
function = constitutive
preservation = required
```

它必须保留身份与论证功能，不能被任意普通例子替换。

### 7.2 说明性案例

说明性案例只帮助理解已经成立的机制或原则。它可以：

- 保留原例；
- 换成等价例；
- 在机制已经讲清的情况下省略。

此类案例标为：

```text
function = illustrative
preservation = replaceable | optional
```

## 8. 最终结论不是独立大奖励项

最终结论通常是关系链的终点，不应在路径之外再次获得一份高权重分数。

如果原书结构是：

```text
假设 H → 反例 E → 机制 M → 限定条件 C → 结论 T
```

候选文章只写出 `T`：

- 可以证明它没有把终点完全写错；
- 但不能获得核心路径分；
- 也不能因为“结论正确”而重复计分；
- 若试跑发现所有模型都能写出 T，则 T 只保留为基本有效性检查，不承担区分模型的主权重。

满分必须要求核心推理路径、关键限定、立场归属和构成性案例全部满足。

## 9. 允许重构，不允许 Judge 补写

关系判定采用“封闭文本重构原则”：

### 允许

- 识别同义表达；
- 解析代词和省略；
- 连接候选文章中分散但明确表达的两条关系；
- 识别显式让步、反驳和限定；
- 接受不改变认知功能的重新排序。

### 不允许

- 因为 Judge 读过原书，就替候选文章补入缺失前提；
- 因为两个概念同时出现，就推断它们存在因果或支持关系；
- 把模糊表达自动解释成正确的作者立场；
- 用原书中的桥接命题填补候选文章没有表达的推理缺口。

边界不是“最多推断一层或两层”，而是：

> Judge 是否引入了候选文章没有表达的实质性命题。

## 10. 证据与判断是两个阶段

“证据”至少有三种不同含义，必须分开命名。

### 10.1 `source_anchor`

证明为什么某个节点或关系有资格进入金标准。它来自原书，属于 Rubric 构建阶段。

### 10.2 `argument_evidence`

作者在书中用来支持、解释或反驳某个观点的案例、数据、实验或思想材料。它是认知结构的一部分。

### 10.3 `submission_evidence`

候选文章中用于判断某条关系是否被保留的引文。它属于运行时审计。

运行时应分成：

```text
Evidence Locator
→ 找候选引文，不给分

Relation Adjudicator
→ 根据目标关系和候选引文做判断

Quote Validator
→ 验证引文存在且没有断章取义

Graph Aggregator
→ 汇总关系覆盖和路径完整度
```

Locator 没找到证据，不应自动等同于模型必然没有表达。正式判缺失前应有全文复查或固定的二次定位规则。

## 11. V1 计分采用两个互补指标

### 11.1 关系覆盖分

对认知结构 `S` 中的关系叶子：

\[
C_S = \frac{\sum_r w_r y_r}{\sum_r w_r}
\]

其中：

- `y_r = 1`：该关系满足冻结标准；
- `y_r = 0`：关系缺失、不足、反转或立场错误；
- `w_r`：该关系在本结构内的局部权重。

这一指标保留渐进分辨率：缺一条关系和全部缺失不会得到相同结果。

### 11.2 核心路径完整率

一条 `mandatory` 路径只有所有关系都通过时才完整。

多个 `alternative` 路径可放入同一 `alternative_group`；该组至少一条完整路径通过即可。

每个认知结构得到一个 `path_complete`：

```text
所有 mandatory 路径完整
且每个 alternative_group 至少一条路径完整
→ 1

否则
→ 0
```

全书按结构权重计算：

\[
P_{book} = \frac{\sum_S W_S path\_complete_S}{\sum_S W_S}
\]

Pilot 阶段同时报告：

```json
{
  "cognitive_relation_coverage": 0.68,
  "complete_core_path_rate": 0.31
}
```

在真实模型试跑和校准之前，不把两者武断地压成一个永久主分。Harbor 若暂时需要单一 `reward`，开发阶段可令其等于关系覆盖分，但必须同时保存路径完整率，且不得据此宣称最终计分已冻结。

## 12. 满分、难度和可达性

Benchmark 不需要为了让现有模型得到高分而降低标准。

但必须满足：

- 经审核的 Oracle 可以在规定篇幅内达到满分；
- 语义等价、组织方式不同的合格重构也能达到高分；
- 只保留最终结论会显著降分；
- 删除一条关键路径会使该结构无法满分；
- 删除构成性案例会失去对应关系和路径分；
- 删除普通说明例不会被机械扣分；
- 关系反转或立场误认会被稳定识别；
- 人工破坏样本和真实模型输出具有可区分分布。

“所有模型都低分”可以是有效结果；“所有正确、错误和破坏样本都得到同样低分”则说明 Rubric 或 Judge 没有分辨率。

## 13. 制作每个认知结构时必须回答的问题

Rubric Builder 和 Human Owner 对每个候选结构依次回答：

1. 作者在这里试图解决的具体问题是什么？
2. 哪些节点是作者主张，哪些是对手观点、假设、让步或被否定观点？
3. 哪些最小有方向关系共同形成作者的判断？
4. 哪些条件、边界或否定范围一旦删除，会把作者判断变成普通口号？
5. 哪些关系必须共同存在，才算恢复完整核心路径？
6. 是否存在多条等价论证路径？哪些可以互相替代？
7. 哪些案例是构成性的，哪些只是说明性的？
8. 哪些顺序变化会改变认知功能，哪些只是表达重组？
9. 一个只知道领域常识、没有读过本书的人会写出什么“看似正确但不足”的版本？
10. 只写最终结论时，具体缺失了哪几条关系？
11. 每个关系能否从原书定位，并能从候选文章独立取证？
12. Oracle 能否在固定篇幅内同时满足所有必需路径？

任何一个问题没有清楚答案，该结构保持 `draft`，不得冻结。

## 14. V1 当前冻结与暂缓项

本文件冻结：

- 评分对象是认知关系图，不是扁平观点列表；
- 最小评分叶子是有方向、可独立判断的关系；
- 节点必须记录角色、立场归属和认识论状态；
- 构成性案例进入主认知结构；
- 具有认知功能的组织进入主分，纯语言风格不进入；
- 最终结论不独立重复计分；
- 公开 instruction 与隐藏 Rubric 分离；
- Pilot 同时报告关系覆盖和完整核心路径率。

本文件暂不冻结：

- 两个主指标最终如何合成为单一排行榜分数；
- 关系反转是否使用负分；
- Judge 的最终状态机与重试次数；
- 每本书应有多少结构、关系和路径；
- 具体书目、权重和任何正式金标准。

这些问题在第一本开发书 Rubric、Oracle 和受控破坏样本完成后再校准。
