# 篇章关系重构评分契约 V1

本文定义一个独立于“认知结构保留”的新维度：`discourse_reconstruction`（篇章关系重构）。它不重新引入模糊的“作者感 1–10 分”，也不评价模型是否模仿原作者的句式和修辞风格。

它回答两个不同问题：

1. **作者关系边恢复**：候选文章是否保留了原书中重要材料之间的篇章关系、层级和论证功能；
2. **编辑性连贯**：候选文章重新组织材料后，是否形成一条真实、必要、不可任意重排的阅读推进。

因此 V1 的两个主要能力维度是：

```text
认知结构保留
→ 写对了什么关系、路径、条件、立场和构成性材料

篇章关系重构
→ 这些内容在文章中承担什么功能，并如何被组织成一篇文章
```

## 1. 为什么需要独立维度

一个输出可能具有很高的认知关系覆盖，却仍然表现为：

- 一个评分点对应一个模块；
- 每个概念采用“定义—案例—下一项”的固定节奏；
- 主体章节可以交换顺序而不明显损伤文章；
- 案例只是证明覆盖，而没有推动论证；
- 开头和结尾很漂亮，但中间没有持续的中心线索。

这种文本可以是高质量知识笔记，却还不是高质量整书重构文章。

反过来，一篇文章也可能局部流畅、整体好读，却没有忠实保留原书关系。两者必须分别报告，不能互相补偿。

## 2. 与认知结构的边界

### 2.1 认知关系

认知结构判断：

> 候选文章是否正确表达了原书中的命题关系、方向、条件、边界、立场和路径？

### 2.2 作者关系边

作者关系边判断：

> 一个已经被正确表达的内容关系，是否在候选文章中继续承担与原书相符的层级、转折、支撑、收束或下游驱动作用？

例如：

```text
原书前部：广告不能创造大众渴望
原书后部：文案必须选择并引导已经存在的主导渴望
```

认知分判断两者的限制关系是否正确。

作者关系边分进一步判断：候选文章是否把前者作为后续标题、市场诊断和创造力判断的控制性前提，而不是在两个独立段落中分别提到它们。

### 2.3 不重复计分

作者关系边采用认知正确性门槛：

\[
a_e = g_e \times (0.5r_e + 0.5d_e)
\]

其中：

- `g_e`：内容门槛。关联的认知关系正确时为 1，否则为 0；
- `r_e`：原书篇章／修辞功能是否被保留，二元；
- `d_e`：后续内容是否实际使用了这条边，二元。

语义正确本身不在作者关系边中再次加分，只作为门槛。

当一条边关联多条认知关系时，V1 采用严格合取门槛：全部关联关系为 `pass` 才有 `g_e=1`；任一关系为 `fail` 则 `g_e=0`，且不再调用该边的 Locator/Judge；任一关系为 `unresolved` 或 `infrastructure_error` 时，该边及作者边总分为 `unscorable`，不得折算成零。校准期望必须把被失败关系严格门控的边列为 changed 或 unfrozen。

## 3. 作者关系边池

不能从全书所有段落中任意随机抽两个段落。绝大多数任意段落对没有直接关系，会产生一个被“无关系”样本主导的虚假稳定指标。

正确流程是：

```text
完整书稿
→ 人工审核的 Source Anchors
→ 有明确意义的作者关系边池
→ 分层固定面板
→ 对所有模型使用同一面板
```

每条边至少记录：

- 两端原书 Source Anchor；
- 与认知 Book Card 的关联关系；
- 关系方向；
- 在全书中的篇章／修辞角色；
- 必须保留的层级、范围、案例功能或收束作用；
- 预期驱动的下游内容；
- 一个或多个错误关系对照；
- 分层类别、权重和是否关键。

### 3.1 推荐边类型

- `premise_to_consequence`：前提推动后续结论；
- `constraint_to_strategy`：能力边界决定策略；
- `problem_to_reframing`：原问题被重新定义；
- `objection_to_rebuttal`：反对意见推动反驳；
- `case_to_inference`：案例引出机制或结论；
- `contrast`：两个概念的对比组织后续判断；
- `condition_to_scope`：条件限制结论范围；
- `turn`：论证方向发生转折；
- `synthesis`：分散章节被汇合；
- `opening_to_closure`：结尾回收开头问题。

### 3.2 推荐修辞角色

- `governing_premise`：全篇控制性前提；
- `problem_reframing`：改变问题定义；
- `contrast`：建立核心区分；
- `objection` / `rebuttal`：提出并处理反对意见；
- `condition` / `boundary`：限制适用范围；
- `example_support` / `counterexample`：案例承担支撑或反驳；
- `turn`：产生必要转折；
- `synthesis`：完成跨章节综合；
- `closure`：完成开头到结尾的回环。

## 4. 作者关系边运行时判断

Judge 读取：

- 原书片段 A 和 B；
- 冻结的正确关系说明；
- 错误方向、并列化或限定删除的 Hard Negatives；
- 候选文章中由 Locator 找到的相关证据；
- 关联的认知关系判决。

Judge 分别输出：

```json
{
  "content_gate": 1,
  "rhetorical_function_preserved": 1,
  "downstream_dependency_preserved": 0,
  "submission_evidence": ["候选文章中的最短引文"],
  "reason": "候选文章保留了转折功能，但后续章节没有实际使用该转折。"
}
```

不得因为 A、B 都出现就自动判定作者关系边成立。

## 5. 分层固定抽样

“随机”只用于冻结前从已审核边池生成面板，不在看到模型输出后重新抽样。

推荐分层：

| Stratum | 典型内容 |
|---|---|
| `global_cross_chapter` | 跨章节控制关系与综合 |
| `local_argument` | 局部前提、转折和推导 |
| `condition_boundary` | 条件、限定和否定范围 |
| `stance_turn` | 反方、让步、反驳和立场转换 |
| `case_function` | 案例在论证中的功能 |
| `opening_closure` | 开头问题和结尾收束 |

冻结规则：

- 使用 `stratified_fixed_panels`；
- 保存随机种子和显式 Edge IDs；
- 所有模型使用相同面板；
- 面板在正式输出前冻结；
- 正式结果后不重新抽边；
- 关键边至少进入一个面板；
- Pairwise Judge 必须进行 A/B 位置反转。

关系边数量提高单书测量稳定性，但不能替代书籍数量。跨书置信区间必须以“书”为聚类单位。

## 6. 编辑性连贯的操作化定义

编辑性连贯不等于“句子没有语病”，也不等于连接词很多。它测量候选文章内部的篇章关系是否真实存在。

### 6.1 局部推进 `local_progression`

从候选文章中按冻结算法抽取相邻段落对，每对判断三个二元项：

1. `relation_identifiable`：能否明确说出两段之间的关系；
2. `forward_dependency`：后一段是否使用前一段建立的前提、问题、区分或反对意见；
3. `advances_argument`：后一段是否增加、修正或推进认识，而不是换一种说法重复。

只有“主题相似”不能算推进。

### 6.2 全局顺序必要性 `global_order`

结构提取器先识别主要文章单元及其字符区间，再构造：

```text
原顺序：A → B
扰动顺序：B → A
```

Judge 只判断哪个顺序更符合思想推进，并执行两次位置反转：

- 原顺序两次均胜：1；
- 一胜一负或差异不足：0.5；
- 扰动顺序两次均胜：0。

判断思想依赖，而不是依赖“前文所述”等表面指代。

### 6.3 中心线连接度 `spine_connectivity`

结构提取器输出：

- 控制性问题或中心命题；
- 主要文章单元；
- 每个单元的功能；
- 字符范围。

可接受功能包括：建立前提、框定问题、提出区分、提出／回答反对意见、发展机制、限定结论、综合、应用和收束。

无法说明如何推进中心线的主要单元记为 `orphan`：

\[
E_{spine}=1-\frac{orphan\ units}{major\ units}
\]

### 6.4 案例嵌入 `example_integration`

从候选文章中抽取案例，判断它是否承担：

- `evidence`；
- `counterexample`；
- `boundary`；
- `turn`；
- `application`；
- `synthesis`。

只在定义后补一个对应故事，且删除或移动后论证不受影响，记为装饰性案例，不通过。

### 6.5 结尾是否由前文挣得 `closure`

同时读取开头、正文功能摘要和结尾，判断：

1. `returns_to_opening`：结尾回答或重新定义了开头的问题；
2. `depends_on_body`：结尾的高层判断依赖正文已经建立的关系；
3. `non_generic`：结尾不能原样替换到大量同领域文章。

## 7. 编辑性连贯聚合

Pilot 默认公式：

\[
E = 0.30E_{local}
+0.30E_{order}
+0.20E_{spine}
+0.10E_{example}
+0.10E_{closure}
\]

这些权重由每本书的冻结 Discourse Card 保存，仍需通过开发书校准。正式报告必须同时保留五个子分，不能只发布一个 `editorial_coherence`。

## 8. 篇章关系重构聚合

每本书先分别得到：

```json
{
  "authorial_edge_recovery": 0.71,
  "editorial_coherence": 0.68
}
```

Pilot 可按冻结权重形成诊断性总分：

\[
D=w_AA+w_EE
\]

默认示例为 `w_A = 0.5`、`w_E = 0.5`。V1 在开发书、Oracle 和受控扰动跑完前，不把 `D` 与认知结构指标永久合成一个排行榜标量。

## 9. 校准扰动

至少制作：

| 扰动 | 预期下降 | 原则上稳定 |
|---|---|---|
| 主要章节交换 | 全局顺序、编辑连贯 | 认知关系覆盖可保持 |
| 转场全部改成“此外／其次” | 局部推进、中心线 | 事实内容 |
| 改成“定义—案例”模块 | 中心线、案例嵌入 | 术语覆盖 |
| 案例移动到错误位置 | 案例嵌入、作者关系边 | 案例数量 |
| 结尾替换为通用总结 | 结尾收束 | 前文认知关系 |
| 语义保持改写 | 不应下降 | 全部实质指标 |

每个扰动必须由人工确认只改变目标变量。

## 10. 统计报告

### 10.1 单书

报告：

- 面板均值；
- Edge／Probe 层面的 Bootstrap 区间；
- Judge 位置反转分歧率；
- 多次 Rollout 均值与标准差；
- 各 Stratum 子分。

### 10.2 跨书

同一本书的边并不独立。跨书比较使用以书为聚类单位的 Bootstrap 或等价分层模型，不能把一百条同书边当成一百本独立样本。

### 10.3 模型直接比较

可在同一冻结边上比较模型 A 与 B，由 Judge 输出 A 胜、B 胜或平局，并进行顺序反转。Pairwise 胜率作为第二报告视角，不能替代绝对维度分。

## 11. Harbor 运行结构

```text
/tests/gold/book_card.json
→ 认知结构

/tests/gold/discourse_card.json
→ 作者关系边池、固定面板和编辑探针配置

/app/submission.md
→ 候选文章

Verifier
├── Cognitive Structure Pipeline
├── Authorial Edge Pipeline
├── Editorial Coherence Pipeline
└── Deterministic Aggregators
```

`reward.json` 只保存数值字段；边、证据、位置反转结果和 Judge 理由进入审计日志。

## 12. 版权边界

Discourse Card 只保存 Source Anchor IDs、关系说明和短证据摘要。正式评分时由私有书稿和 Locator 根据稳定位置提取必要短片段，不在公共仓库提交受版权保护的长段原文。

开发 Task 可以仅使用 Book Card 的短证据摘要来验证协议接线，但必须在审计日志中标记 `development_only`；这种运行不能冻结为正式 Authorial Edge 分数。正式运行必须改用经人工确认的私有短摘录，并冻结摘录边界或子锚规则。

## 13. 当前冻结与暂缓项

本文件冻结：

- 篇章关系重构是认知结构之外的独立维度；
- 它由作者关系边恢复和编辑性连贯组成；
- 作者关系边来自审核后的有意义边池，不来自任意段落对；
- 认知正确性是作者关系边的门槛，不重复奖励；
- 编辑性连贯使用候选内部关系和受控扰动；
- 抽样面板对所有模型一致，并在正式输出前冻结；
- 纯句式模仿和“人味”不进入该维度。

本文件暂不冻结：

- 认知结构与篇章关系重构如何合成最终排行榜标量；
- 每本书应有多少作者关系边；
- 最终 Judge 模型和重试状态机；
- 跨书统计模型的最终实现。
